# always-latest-deps

## Purpose
- This repository contains a small cross-agent package that blocks direct edits to dependency manifest files and steers Pi and Claude toward the right package manager command instead.
- Keep changes tightly focused on that shared dependency-policy behavior and its adapters.

## Stack
- TypeScript
- Vitest
- Pi adapter API from `@mariozechner/pi-coding-agent`

## Project Layout
- `extensions/package-manager-interceptor.ts` is the Pi adapter.
- `shared/dependency-policy.mjs` is the single source of truth for manifest protection rules, command resolution, and shared messaging.
- `claude/hooks/dependency-manifest-guard.mjs` adapts the shared policy to Claude Code `PreToolUse` hooks.
- `setup/claude-renderers.mjs` renders reusable Claude bundle text and project-local shim content.
- `setup/claude-setup.mjs` powers `npx always-latest-deps setup`.
- `claude/skill/CLAUDE.md` is the reusable Claude bundle shipped by this library.
- Root `CLAUDE.md` stays project-owned and should only contain repo-local memory plus the managed import block.
- `.claude/imports/always-latest-deps.md`, `.claude/hooks/always-latest-deps.mjs`, and `.claude/commands/add-dependency.md` are project-local shims generated by setup.
- `extensions/package-manager-interceptor.test.ts`, `shared/dependency-policy.test.ts`, `claude/hooks/dependency-manifest-guard.test.ts`, and `setup/claude-setup.test.mjs` cover adapter and setup behavior.
- `vitest.config.ts` configures the test runner.
- `README.md` describes the package intent, setup flow, and supported ecosystems.

## Commands
- Install dependencies: `npm install`
- Run tests: `npm test`
- Run typecheck: `npm run typecheck`
- Refresh package-owned Claude assets: `npm run generate:claude`
- Refresh this repo’s local Claude shims: `npm run setup:self`

## Working Rules
- Preserve the core product behavior: agents should not edit dependency manifests directly.
- Prefer minimal, surgical changes over broad refactors.
- Keep manifest protection policy centralized in `shared/dependency-policy.mjs`; adapters should stay thin.
- Keep root `CLAUDE.md` project-owned, and keep reusable Claude policy text in `claude/skill/CLAUDE.md` plus project-local shims under `.claude/`.
- When changing interception behavior, update or add tests in the shared core and any affected adapter or setup tests in the same pass.
- Keep user-facing block reasons and notification text clear and actionable.
- Follow existing code style unless there is a strong local reason to improve consistency.

## Dependency Management
- Do not manually edit `package.json` or other dependency manifests to add or change dependencies unless the user explicitly asks for that exact file edit.
- Prefer package-manager commands such as `npm install`, `pnpm add`, `yarn add`, `bun add`, `pip install`, `bundle add`, `cargo add`, `go get`, or `deno add`.
- Avoid pinning versions by hand when the package manager should resolve the latest appropriate version.

## Testing Expectations
- For logic changes, run the most targeted Vitest coverage available first, then broader tests if needed.
- If you cannot run tests, say so explicitly and summarize what should be verified.

## Agent Notes
- Read the extension and its tests before changing behavior.
- Treat this as a library-style repo: avoid introducing app-style scaffolding or unrelated tooling.
- Update `README.md` when supported manifests or package-manager guidance changes.
- Regenerate package-owned Claude bundle assets with `npm run generate:claude` after changing shared policy text or supported manifest rules.
- Refresh this repo’s local Claude shims with `npm run setup:self` after changing setup renderers or setup merge behavior.
